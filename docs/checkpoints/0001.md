### Implementation map

- src/main.rs: new, play, turn, inspect, export and schema commands. The interactive loop supports typed actions, numbered choices, /state, /help and /quit. Ctrl-C cancels inference. New saves and exports refuse overwrite.
- src/models.rs and src/state.rs: strict typed output plus semantic validation, canonical identities and appearances, inventory/flags/relationships/objectives/plot threads, scene metadata and memory. NPC dialogue cannot invent player speech. Every fourth turn requires a bounded summary update.
- src/database.rs: SQLite WAL, foreign keys, full synchronization, version-checked atomic commits, prompt/raw-response/before-after audit and interrupted-attempt recovery. Relevant memory retrieval is bounded; full prose remains in the audit.
- src/prompt_builder.rs and prompts/story_system.txt: a bounded state projection, six selected memories, summary, two recent structured scenes and the output schema. Repairs use unchanged state, an explicit error, temperature zero and a recorded new seed.
- src/story_engine.rs and src/inference/: model-independent StoryBackend, JSON stdin/stdout worker protocol, process-group timeout/cancellation, output limits, worker reaping and project-level single-worker locks.
- workers/gemma/worker.py: offline MLX worker, actual model chat template/tokenizer and EOS IDs, token budget check, memory limits, measured timings where available. workers/gguf/worker.py: short-lived private loopback llama-server with native tokenizer and JSON grammar; explicit CPU option.
- scripts/: local installers, model selection, launch/build/check wrappers, Metal verification and repeatable benchmarks. Use these wrappers so tool caches and Rust/Python state remain project-local.
